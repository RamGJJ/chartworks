# ChartWorks

밴드 악보 PDF를 손보는 도구 모음입니다. 지금은 세 가지를 합니다 — **코드 키 변경**,
**탭 프렛 옮기기**, **악보에 메모 적기**.

키를 바꾸면 악보에 적힌 **코드 심볼**을 옮겨 적습니다. 오선의 음표와 조표는
원본 그대로 둡니다 (코드 보고 반주하는 사람을 위한 도구입니다).

```
C  +1  →  C#        Gm7  -1  →  F#m7        E/G#  +1  →  F/A
```

베이스만 바꾸는 표기(`/E` — 앞 코드는 그대로, 베이스만 E)도 따로 인식해서 옮깁니다.

탭 악보라면 **프렛 숫자도** 같이 옮깁니다. 기본은 코드와 같은 값으로 함께 움직이고,
체크를 풀면 따로 조절할 수 있습니다 — 코드만 바꾸거나, 탭만 바꾸거나, 서로 다른
값으로 두는 것도 됩니다.

## 쓰는 법

### 웹

```
npm install
npm run dev          # http://localhost:5181
```

1. PDF를 끌어다 놓으면 코드 심볼을 찾아 파란 네모로 표시합니다.
2. `+`/`−` 또는 목표 키로 얼마나 옮길지 정합니다.
3. 네모를 누르면 그 코드 하나만 건너뛸 수 있습니다.
4. 못 찾은 코드는 **코드 직접 잡기**로 네모를 그려 넣습니다 (아래 참고).
5. **저장 폴더 고르기**(Chrome·Edge) 또는 그냥 **변환해서 저장**(다운로드 폴더).

#### 코드 직접 잡기

자동으로 못 찾았거나 잘못 읽은 코드를 손으로 지정합니다. 버튼을 켜고 코드 위를
드래그하면:

- **글자가 읽히면** 그대로 코드로 잡습니다. 위치·크기·글꼴은 그 글자에서 가져옵니다.
- **글자가 없으면**(스캔 악보) 입력창이 떠서 직접 적습니다. 원래 코드를 적으세요 —
  반음 수를 바꾸면 따라 움직입니다. 글자 크기는 그 악보가 이미 쓰고 있는 코드
  크기에 맞추고, 없으면 종이 크기에서 뽑습니다.
- 이미 잡혀 있는 코드 위에 그리면 **그 코드를 대신합니다**. 잘못 읽은 코드를
  고칠 때 쓰면 됩니다.

직접 잡은 코드는 노란 네모로 표시되고, 저장될 모습 그대로 미리 그려집니다.
누르면 지워집니다.

#### 글자 넣기

악보에 메모를 적습니다 — `2번만 반복`, `Gt.2 쉬어감` 같은 것들. 코드가 아니므로
키를 바꿔도 **그대로 남습니다**.

- 버튼을 켜면 위에 **글자 크기** 바가 뜹니다. 넣을 자리를 누르면 입력창이 나오고,
  적은 뒤 **✓** 로 넣고 **✕** 로 뺍니다. Enter 로도 넣어집니다.
- 넣은 글자는 **끌어서 옮기고**, **눌러서 고칩니다**. 고치는 동안에는 위 바가 그 글자의
  크기를 보여주고, 바꾸면 바로 반영됩니다.
- 화면에 보이는 그대로 PDF에 들어갑니다 (같은 글꼴로 미리 그립니다).

직접 잡은 코드와 넣은 글자는 **메모리에만** 있습니다. 저장 전에 창을 닫거나
새로고침하면 사라집니다.

원본 파일은 절대 건드리지 않습니다. 결과는 `<원래이름> [새키].pdf` 로 나갑니다.

### 명령줄 (여러 장 한꺼번에)

```
npm run transpose -- --in "D:/medit_band/악보" --out "./output/+2" --semitones 2
```

| 옵션 | 설명 |
|---|---|
| `--in` | PDF 파일 하나 또는 폴더 (하위 폴더까지 훑습니다) |
| `--out` | 결과를 쓸 폴더. 입력 폴더 안이면 거부합니다 |
| `--semitones` | 코드를 옮길 반음 수 (`-11` ~ `11`) |
| `--frets` | 탭 프렛을 옮길 반음 수. 코드와 따로 둡니다 |
| `--max-fret` | 프렛 상한 (기본 24). 넘으면 그 악보는 건너뜁니다 |
| `--style` | `auto`(기본) / `sharp` / `flat` |
| `--glyph` | `ascii`(기본, `#`·`b`) / `unicode`(`♯`·`♭`) |
| `--font` | `auto`(기본) / `helvetica` / `helvetica-bold` / `times` / `times-bold` |
| `--debug` | 지운 자리를 노란 네모로 칠해 위치를 확인 |
| `--dry-run` | 쓰지 않고 무엇이 바뀔지만 출력 |

## 동작 방식

1. **추출** — pdf.js 로 글자마다 위치·크기·폰트를 받습니다.
2. **묶기** — 같은 베이스라인에서 가까이 붙은 글자를 한 덩어리로 만듭니다.
   `C` + 음악 폰트의 `♯` + `m` 이 `C#m` 하나가 됩니다. 글자는 가장 **가까운**
   덩어리에 붙습니다 — 먼저 찾은 덩어리에 붙이면 코드의 `♯`이 옆 음표 머리에
   끌려가 `C#m` 이 `C` + `m` 으로 쪼개집니다.
3. **거르기** — 코드 문법에 맞는 덩어리만 남기고, 문서 안에서 코드가 몰려 있는
   폰트에 속하지 않으면 버립니다. TAB 클레프의 `A`·`B`, 보표의 임시표,
   옆에 붙은 음표 머리는 코드로 세지 않습니다.
   한 덩어리가 통째로는 코드가 아니면, 글자 경계에서 잘라 **조각이 모두 코드일
   때만** 나눕니다 (`A7sus4A7` → `A7sus4` + `A7`). 그래서 `Guitar 1` 같은 글은
   낱자로 흩어지지 않습니다.
4. **키 추정** — 24개 후보 조를 화성 적합도로 채점합니다 (단순 빈도수가 아닙니다).
5. **표기** — 조가 움직인 만큼 음이름 자리도 옮깁니다. 그래서 `Db +2` 가 `D#`
   가 아니라 `Eb` 로 나옵니다. `E#`·`B#`·`Cb`·`Fb` 처럼 읽기 나쁜 철자는 피합니다.
6. **쓰기** — pdf-lib 로 원래 글자 위에 흰 네모를 덮고 새 코드를 그립니다.
   글꼴은 원본 글자 폭에 가장 가까운 것을 자동으로 고릅니다.

## 탭 프렛 옮기기

같은 줄에서 프렛을 N칸 올리면 소리도 N반음 올라갑니다. 튜닝이 Drop D든 반음
내림이든 모든 줄에 같은 수를 더하므로 계산은 그대로 성립합니다.

문제는 범위입니다. **올리는 쪽은 거의 다 되지만 내리는 쪽은 대부분 막힙니다** —
개방현(0번 프렛)이 음수가 되기 때문입니다. 악보 350개 기준:

| | -3 | -2 | -1 | +1 | +2 | +3 | +5 |
|---|---|---|---|---|---|---|---|
| 24프렛 안에 들어오는 악보 | 4 | 7 | 17 | **128** | **128** | 126 | 116 |

(탭이 있는 악보 129개 기준)

하나라도 범위를 벗어나면 **그 악보는 통째로 건너뜁니다.** 일부만 옮기면 악보가
틀어지기 때문입니다. UI에 몇 개가 왜 걸리는지 표시됩니다.

찾아낸 프렛은 미리보기에 네모로 표시됩니다 — 그대로면 초록, 옮기면 파랑,
**범위를 벗어나 막힌 것은 빨강**입니다. 올려놓으면 `7 → 9프렛`처럼 알려주고,
안 옮길 때는 몇 번 줄 몇 프렛인지 보여줍니다.

코드든 프렛이든 **바뀔 내용이 제자리에 그대로 그려집니다.** 저장하기 전에 결과를
그대로 보는 셈입니다. 원래 값은 네모 위에 올려놓으면 알려주고, **악보를 길게 누르고
있으면** 이 도구가 그린 것이 전부 걷히면서 원본이 드러납니다. 옮길 수 없는 악보는
아무것도 안 바뀌므로 미리보기도 원본 그대로 둡니다.

동작 방식: Finale은 탭 숫자를 **줄 선 → 숫자 뒤 흰 사각형 → 숫자** 순으로 그립니다.
같은 순서로 다시 그리되, 지울 범위는 원래 숫자와 새 숫자를 합친 넓이로 잡습니다.
그래서 한 자리가 두 자리가 되어도 줄 선을 뚫지 않고, 두 자리가 한 자리가 되어도
줄 선에 구멍이 남지 않습니다. 숫자는 원래 자리를 가운데 두고 한 칸씩 찍습니다.

## 알아둘 점

- **오선과 탭은 그대로입니다.** 조표도 바뀌지 않습니다. 코드만 바뀝니다.
- **스캔한 악보는 자동으로 못 찾습니다.** 글자 레이어가 없기 때문입니다.
  **코드 직접 잡기**로 손수 지정하면 변환할 수 있습니다.
- **암호가 걸린 PDF는 거부합니다.** 조용히 원본과 똑같은 파일이 나오는 것보다 낫습니다.
- **한글 메모가 있으면 파일이 커집니다.** 한글을 쓰려면 글꼴을 PDF에 넣어야 하는데,
  pdf-lib 의 subset 이 이 글꼴을 망가뜨려서 통째로 넣습니다 (약 780KB 증가).
  로마자만 쓴 메모는 내장 글꼴로 적으므로 커지지 않습니다.
- **탭을 한 번 옮긴 악보는 다시 못 옮깁니다.** 흰 사각형 아래 옛 숫자가 남아 있어
  어느 쪽이 위인지 가릴 수 없기 때문입니다. 감지해서 거부하니 틀린 결과가 나오진
  않습니다. 원본에서 다시 하세요.
- **오선 음표는 그대로입니다.** 탭만 옮기면 같은 페이지의 오선과 어긋납니다.
  탭을 보고 치는 사람에게는 문제없지만, 알고 쓰셔야 합니다.
- **원래 글자는 흰 네모 아래 남아 있습니다.** 보이지는 않지만 PDF 안에서 복사·검색하면
  옛 코드가 딸려 나옵니다. 같은 파일을 다시 변환하는 것은 괜찮습니다 — 위에 덮인
  글자만 읽도록 되어 있습니다.

## 화면 크기

| 폭 | 생김새 |
|---|---|
| 1024px 이상 | 설정 패널과 악보가 나란히 |
| 768~1023px | 같은 배치에 패널만 좁게 |

악보는 열 때 **폭에 맞춰** 들어옵니다. 확대·축소를 누르면 그 뒤로는 누른 배율을 지킵니다.

브라우저 스크롤을 막아서, 그 밖에서는 악보를 평소처럼 쓸어 넘길 수 있습니다.
